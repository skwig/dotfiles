# Hyprland 0.57.0 Migration Implementation Plan

> Historical initial plan: its refactored Lua layout and event-based todo design
> are superseded by `2026-11-12-hyprland-literal-port.md` at the user's request.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate this repository's Hyprland setup from Hyprlang to Lua for exactly Hyprland 0.57.0, preserving existing workflows.

**Architecture:** Port the existing file split to small Lua modules, passing host settings explicitly rather than using Hyprlang globals. Keep NixOS/Home Manager responsible for package selection and host-specific symlinks. Migrate shell IPC callers alongside the config, and stage activation separately from implementation.

**Tech Stack:** Hyprland 0.57.0 Lua API, Bash, NixOS, Home Manager, UWSM, hypridle.

**Spec:** User request: create a migration plan for 0.57.0. The proposed scope and decisions below are for review, not an approved implementation design. No migration or activation has been performed.

## Proposed scope and approaches

- **Recommended: direct Lua port.** Preserve settings, commands, rules, two modifier sets, and host-specific monitor topology. Small helper functions replace repeated `source` directives. This minimizes behavioral changes.
- **Alternative: broader Lua redesign.** Replace the VM socket watcher and focus scripts with compositor-native events. Potentially cleaner, but changes lifecycle and focus behavior at the same time as the upgrade; defer it.
- An automated converter, if available, can provide a draft, but cannot establish compatibility of the external scripts, NixOS wiring, or session manager. Do not use generated output as the acceptance test.

## Global constraints

- Target **0.57.0**, not an unspecified current unstable version.
- Preserve behavior on **blackbox** and **smallbox**. `vmbox` imports the Hyprland module but has no tracked host-specific Hyprland symlinks; audit its deployment before including it in rollout, without inventing a monitor layout.
- Preserve UWSM/greetd, DMS, the master layout, current animation timings, and application commands. Do not copy upstream example defaults over existing choices.
- Keep `hypridle.conf` in its existing format: Hyprland dropping Hyprlang does not mean hypridle drops its own config parser. Only migrate the embedded Hyprland IPC commands.
- Preserve all pre-existing tracked and untracked work. In particular, `nixos/flake.lock` and `nixos/hosts/blackbox/configuration.nix` were already modified when planning started, and three focus scripts were untracked.
- Do not switch the live session, update the lock file, or remove old configs until the staged Lua configuration has passed validation and the user authorizes activation.
- Implement in an isolated worktree/staging directory, not the directory targeted by live out-of-store links. Bring the relevant dirty/untracked baseline into staging explicitly without discarding it. Adding `hyprland.lua` to the live directory can affect config selection even before a NixOS switch.
- NixOS rollback and dotfile rollback must be paired: these Home Manager links point outside the Nix store.

## Verified findings (2026-11-11)

- Installed binary and running compositor both report **0.56.2** (`Hyprland --version`, `hyprctl version`).
- The official **v0.57.0** release includes “config: remove legacy config support” (#15539). The old language is **Hyprlang**, rather than “hyprscript”; the replacement is Lua, with `hyprland.lua` as the entrypoint.
- `hypr/hyprland.conf` loads host globals/monitors, general keybindings, the main-modifier fragment twice (`SUPER ALT`, then `SUPER`), workspace placement, and app rules.
- The repeated main-modifier fragment also registers the todo workspace/rule twice. In Lua, register shared rules once and generate only the bindings twice.
- `programs.hyprland.package` is `pkgs-unstable.hyprland`; the package version selected by the edited lock file has **not** been evaluated. Installed version is not proof of the next rebuild's version.
- The v0.57.0 IPC implementation interprets `hyprctl dispatch` arguments as Lua dispatcher expressions, not old `workspace 5`/`dpms on` strings.
- `on_created_empty` is still implemented in v0.57.0, but deprecated in favor of `workspace.created` and checking `is_empty`. Prefer the event handler for the todo workspace, with an explicit behavior test.
- `misc.disable_watchdog_warning`, `misc.disable_splash_rendering`, and `input.float_switch_override_focus` still exist in the tagged source; do not remove them speculatively.

## Review focus

1. Both modifier sets and VM submap escape bindings survive; normal bindings must not accidentally become VM bindings.
2. Reloading must not duplicate bindings, rules, event handlers, or autostart processes.
3. Monitor/workspace placement and scaling must work independently for each host, including missing/disconnected outputs.
4. Regexes, expression-based window sizes, silent workspace moves, and screen-share privacy must retain their meanings.
5. A successful NixOS build must not be mistaken for successful Lua parsing or functioning external IPC consumers.

## File map

| File | Responsibility/change |
| --- | --- |
| `hypr/hyprland.lua` | New entrypoint; host loading, settings, startup, animations, gestures, workspace rules |

| `hypr/keybindings.lua` | New ordinary bindings and `register_main_mod(mod)` function, including VM submap bindings |
| `hypr/apps.lua` | New named window/layer rules; todo rule and one workspace-created handler |
| `hypr/hypridle.conf` | Retain parser syntax; replace embedded DPMS dispatcher calls |
| `bin/vm-submap-on-vm-focus.sh` | Replace dispatcher calls; retain socket watcher architecture |
| `bin/dots-focus-layout.sh` | Replace focus/move/fullscreen/workspace dispatcher calls |
| `bin/dots-focus-{linuxvm,windowsvm,runelite}.sh` | Audit existing untracked scripts; migrate callers if retained, without rewriting user work |
| `nixos/hosts/{blackbox,smallbox}/configuration.nix` | Replace two host `.conf` symlinks with `.config/hypr-custom/host.lua` pointing to the appropriate host table |
| `nixos/modules/hyprland.nix` | Confirm package/portal selection and UWSM integration; update only if needed |
| `nixos/flake.nix`, `nixos/flake.lock` | Conditional package pin/update, only if current inputs do not yield 0.57.0 |
| `tests/hypr/config.lua` | New Lua registration/behavior tests using a recording `hl` stub |
| `tests/hypr/ipc.sh` | New shell tests with fake `hyprctl`, `socat`, and client fixtures |
| `docs/hyprland-migration.md` | Activation, compatibility findings, smoke tests, paired rollback instructions |

Leave old Hyprland `.conf` files intact until acceptance; remove only the superseded eight compositor files in a separate cleanup change, never `hypridle.conf`.

## Task 2: Port host settings and compositor configuration

**Files:** Create `hypr/hyprland.lua`, `hypr/host.blackbox.lua`, `hypr/host.smallbox.lua`, `tests/hypr/config.lua`.

**Interfaces:** Each host module returns `{ main_monitor, left_monitor, center_monitor, right_monitor, scale, monitors }`, with string monitor names, numeric scale, and a list of `hl.monitor` tables. Entrypoint loads the deployed `~/.config/hypr-custom/host.lua` using the configured XDG config directory, then applies the returned data. Test runner accepts `lua tests/hypr/config.lua blackbox` or `smallbox` and injects host data without touching the user's deployed links.

- [ ] Write recording-stub tests first, failing until the Lua files exist: blackbox has DP-1 center/highrr/0x0, HDMI-A-1 left and DP-2 right at 2560x1440@75, scale 1.25; smallbox has eDP-1/highrr/0x0 at scale 2.0, with all workspace monitor roles pointing to eDP-1.
- [ ] Port typed values with `hl.config`, `hl.env`, `hl.monitor`, `hl.device`, `hl.gesture`, `hl.curve`, and `hl.animation`, using the **v0.57.0** API. Use `require` for tracked modules and verify host/module edits are watched on reload; do not swallow missing-host errors with a broad `pcall`.
- [ ] Preserve master/slave placement and `mfact=0.5`, gaps 4/8, border 1, rounding 5, gradient colors/angle, opacity, blur, shadow, XWayland zero scaling, Caps-to-Escape, `follow_mouse=2`, touchpad natural scrolling/factor 0.25, mouse sensitivity -0.85, four-finger horizontal swipe/distance 400, and all active animation speeds. Do not replace Bezier animations with the example's springs.
- [ ] Replace `exec-once` with a single `hyprland.start` subscription running the existing five commands. Assert that loading the module alone executes none of them and firing startup executes each once; reload must not re-run startup commands.
- [ ] Register workspace rules 1–9 once: 1–5 persistent on center, 6–7 left, 8–9 right. Assert every mapping in both host tests. Add missing-output behavior to the live checklist rather than claiming a recording stub simulates monitor fallback.
- [ ] Run both host test commands and `luac -p` separately for every new Lua file. A syntax/stub pass is not proof the real Hyprland API accepts it. Commit the port and its tests without activating it.

## Task 3: Port bindings, rules, and special-workspace behavior

**Files:** Create `hypr/keybindings.lua`, `hypr/apps.lua`; extend `hypr/hyprland.lua`, `tests/hypr/config.lua`.

**Interfaces:** `keybindings.lua` exports `register()` and `register_main_mod(mod: string)`; the entrypoint calls `register()` once and `register_main_mod` for `SUPER ALT` and `SUPER`. `apps.lua` exports `register()` and registers shared rules/events once.

- [ ] Add failing assertions for both complete binding sets, ordinary screenshot/media bindings, locked/repeating flags, silent workspace moves (`follow=false`), and mouse drag/resize flags. Register the VM submap with `hl.define_submap`; include both modifier variants of R, bracket navigation, and C inside it. Assert those bindings do not leak into or out of the submap.
- [ ] Port bindings to dispatcher **closures**, e.g. `hl.dsp.focus({workspace=5})`, `hl.dsp.window.move({workspace=5, follow=false})`, and `hl.dsp.window.float({action="toggle"})`. Preserve every existing shell command. For Shift+W, dispatch float toggle then pin toggle in order, without leaving old `hyprctl` strings embedded in a shell command.
- [ ] Port all app/layer rules with unique names and nested `match` tables. Preserve rule ordering, class vs initial-class/title selectors, app workspace placement, idle inhibition, Bitwarden `no_screen_share`, XWayland no-focus conditions, layer blur, VM fullscreen, and both expression-based and fixed sizes. Use Lua long-bracket strings for backslash-heavy regular expressions.
- [ ] Register the todo float/1850x1000/center rule once. Implement one `workspace.created` handler that launches `dots-browser --app="https://todo.skwig.party"` only for the newly created empty todo special workspace. Inspect tagged event payload/workspace naming before writing the predicate; test empty todo, nonempty todo, unrelated workspace, and reload cases. Merely toggling an existing workspace must not create another browser.
- [ ] Run both host registration tests. Assert unique rule names, no duplicated shared rules/handlers, and exact Bitwarden/VM/RuneLite match strings. Validate with the real 0.57.0 verifier in Task 5, then commit these files and tests.

## Task 4: Migrate external IPC consumers

**Files:** Modify `bin/vm-submap-on-vm-focus.sh`, `bin/dots-focus-layout.sh`, retained `bin/dots-focus-{linuxvm,windowsvm,runelite}.sh`, `hypr/hypridle.conf`; create `tests/hypr/ipc.sh`.

**Interface:** Preserve existing script command-line interfaces and socket2 focus behavior. Every `hyprctl dispatch` call supplies one correctly quoted Lua dispatcher expression.

- [ ] Add failing fake-IPC tests for active QEMU/VMware window → VM submap, ordinary/empty focus → default submap, focus-layout placements, fullscreen set/unset ordering, multiple same-class clients, no matching clients, and final workspace focus. Stub `socat` so watcher tests terminate without touching the real session.
- [ ] Translate dispatch calls using the tagged API. Examples: `hyprctl dispatch 'hl.dsp.submap("vm")'`, `hyprctl dispatch 'hl.dsp.focus({workspace=5})'`, `hyprctl dispatch 'hl.dsp.dpms({action="on"})'`. Check the tagged submap reset semantics before selecting the default-submap expression; do not assume the old `reset` token is a Lua submap name.
- [ ] Use `hl.dsp.focus({window="address:..."})`, `hl.dsp.window.move({workspace=..., window="address:...", follow=false})`, and `hl.dsp.window.fullscreen({mode="fullscreen", action="set"})` equivalents for focus helpers. Validate/escape shell-supplied values before interpolating into Lua, particularly the generic helper's workspace argument. Add an invalid/injection-shaped workspace test.
- [ ] Change all five DPMS calls in `hypridle.conf`, preserving timeouts 60/300/360 and existing lock predicates. This is an IPC migration, not a lock-screen redesign.
- [ ] Audit the three untracked scripts with the user-work constraint in mind: either migrate their active dispatch calls in place, or obtain agreement to replace them with existing generic-helper wrappers. Do not silently discard them or preserve a malformed legacy `fullscreen set` expression by transliterating it blindly.
- [ ] Search **all file types** for `hyprctl`, socket commands, and Hyprland dispatch usage. Include executable files without extensions and any DMS, hyprshot, or other external consumers; runtime incompatibility in an external package is a rollout blocker, not fixed by a Lua syntax pass.
- [ ] Run `bash tests/hypr/ipc.sh` and `bash -n` on changed scripts. Require recorded arguments to be Lua expressions, no real dispatches during tests, and no legacy active dispatch calls left in deployed files. Commit only the selected scripts/config/tests.

Check DMS and hypridle user service logs.
- [ ] Reload twice: no duplicate bindings/rules, no extra clipboard watcher/VM watcher/Synology/librepods processes, and no new todo browser. Edit a host/module file and verify reloading sees it. Test disconnected/reconnected outputs and fallback workspace placement.
- [ ] Repeat activation and host-specific checks on smallbox after blackbox acceptance. No rollout to vmbox without its deployment audit.
- [ ] After acceptance, remove only the eight obsolete `hyprland*.conf` files and stale references. Keep `hypridle.conf`. Commit cleanup independently, with verification results and recovery instructions in the documentation.

### Rollback procedure

1. From a TTY, stop/exit the failed graphical session; select the previously working NixOS generation (or boot it).
2. Restore the saved **working-tree config contents**, including `hypridle.conf`, changed focus/VM scripts, and host symlink arrangement. Remove/move the newly added Lua entrypoint out of the deployed directory so the older compositor cannot select it unexpectedly. Do not use a broad Git reset or discard unrelated work.
3. Start the old session and confirm old compositor version, zero config errors, working keyboard bindings, and DPMS/submap helpers. Keep the migration branch/staged build for diagnosis.
